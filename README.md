# ⚠️ Copyright (c) 2026 DRAVBER. Лицензия: [LICENSE.md](LICENSE.md). Контакт автора: Telegram @xDRAVBER.

Тестовый MVP сайта студии: портфолио, услуги, интерактивный блок, форма обращения и админка с CRUD и сортировкой проектов. Дизайн адаптирован для телефона, планшета и компьютера.

## Запуск

Нужны Node.js и npm. Из корня проекта:

```sh
npm install
npm run dev
```

Сайт: http://localhost:5173. API: http://localhost:4000/api. Vite перенаправляет запросы /api на сервер.

Настройки сервера находятся в server/.env; образец — server/.env.example. Для отдельного адреса API задайте VITE_API_URL в web/.env перед сборкой. При использовании встроенного сервера менять его не нужно.

## Собранный сайт

```sh
npm run build
npm start
```

Express отдаёт web/dist и API на одном порту, по умолчанию http://localhost:4000. Не используйте Vite dev server для размещения собранного сайта.

## Админка и проекты

Откройте «Админка» внизу страницы или /#admin. Тестовые данные входа сохранены: 123 / 123.

Первые четыре проекта показываются на главной; архив содержит весь список, поиск и категории. В админке доступны добавление, редактирование, удаление и сортировка. На телефоне удобно менять порядок стрелками; перетаскивание запускается за ⋮⋮.

Проекты хранятся в server/src/data/projects.json. PROJECTS_DATA_FILE позволяет задать другое расположение, например постоянный том при размещении. Запись заменяет целый файл атомарно; при ошибке записи API возвращает 503 и состояние не меняется. Повреждённый файл блокирует запуск с понятной ошибкой, не подменяется демонстрационными проектами. Файловое хранилище рассчитано на один серверный процесс.

Изображения размещайте в web/public/photo и указывайте /photo/имя.png. Также поддерживаются URL http(s)://. Файлы в src не подходят для адресов из JSON.

## Подключение почтового сервиса

Точка подключения: server/src/modules/contacts/contacts.delivery.js, функция deliverContact(entry), помеченная TODO(mail).

Она получает имя, email, текст сообщения и ID обращения. URL провайдера, ключ API и адрес получателя храните в переменных окружения сервера. После подтверждения от провайдера верните { delivered: true }; при сбое выбросьте ошибку. Используйте entry.id как ключ идемпотентности, если сервис это поддерживает.

Пока провайдер не подключён, письма не отправляются и обращения остаются в памяти процесса. Интерфейс показывает тестовый режим и предлагает прямые контакты. Это намеренно оставлено для текущего тестового билда.

## Прокси

По умолчанию TRUST_PROXY=false: заголовок X-Forwarded-For от клиента не влияет на ограничение отправок. При размещении за обратным прокси задайте его доверенные IP/подсети, например TRUST_PROXY=loopback для локального прокси. API должен быть доступен через этот прокси; настройка должна соответствовать реальной схеме размещения.

## Проверки

Скрипт npm test оставлен по просьбе владельца. Для запуска проверок без указанного в нём каталога:

```sh
node --test server/src/lib/validate.test.js server/src/lib/rate-limit.test.js server/src/modules/projects/projects.repo.test.js server/src/tests/api.test.js
```

Проверки используют временные хранилища: проверяют CRUD, сохранность при сбоях записи/замены файла, неправильные данные, сессии, выход и ограничение заявок. Основной projects.json они не изменяют.
